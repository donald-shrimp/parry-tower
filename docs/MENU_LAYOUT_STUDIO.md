# メニューレイアウト工房

## 開き方

`node scripts/serve-local.js 8017` を実行し、[レイアウト工房](http://127.0.0.1:8017/layout-studio.html)を開く。[本編のローカル候補](http://127.0.0.1:8017/)も同じ設定で動く。

画面の選択後、主操作と下段ボタン順を指定する。主操作・サブボタンそれぞれにピクセルフォントの切り替えがあり、確定版では主操作は全画面で有効、サブボタンは一時停止だけ有効。「画面全体の並び」で見出し・記録・操作欄を上下移動でき、記録・シンボル・英語小見出しは表示を切り替えられる。操作自体は非表示にできない。「大きさ・余白」はスマホ（600px以下）とPCを別々に編集する。主操作の文字サイズに加え、「サブボタンの文字サイズ」を10〜24pxで指定できる。既存の保存データでは未設定を従来の12pxとして読み込む。プレビュー幅は320/390/520/960/1280px、縦は844px。収まらないときは表示だけ縮小し、CSSの画面幅は指定値を保つ。記録や結果は見本値。

「つづきからあり」で保存データがあるタイトルを確認できる。おすすめ（自動）では、保存があれば「つづきから」、なければ「塔に挑戦する」が主操作になる。明示的に「つづきから」を主操作に指定しても、保存がない状態では「塔に挑戦する」を代わりに置く。採用中との比較、画面単位のリセット、JSON入出力も使える。

下書きは専用キー `parry.menu-layout.draft.v1` へ自動保存。「保存」でローカルファイルへ残し、直前版を `project.backup.json` に保存する。読み込み時はファイルと下書きの新しい方を開く。プレイヤーのセーブや文言エディタの編集ファイルは変更しない。

## 今回の範囲

タイトル・挑戦終了・一時停止の3画面。主要操作を単独の段へ置き、ピクセルフォントを適用する。中断データがあるタイトルは「つづきから」を主操作にする。補助操作は下段のグリッドに並べる。

画面ごとに主操作、補助ボタンの順序、見出し/記録/操作欄などの順序、スマホ/PC別の幅・文字サイズ・列数・間隔を調整する。移動には既存DOMを使い、操作イベント・hidden・disabled・敗北直後の入力ロックを維持する。DOM順と表示順を一致させる。

## 共通の設定とプレビュー

`assets/menu-layout.js` は設定の検証とDOMへの適用、`assets/menu-layout-config.js` は採用済み設定を担当する。本編とDevは同じ設定・CSSを使用する。工房は実際のindex.htmlを読み、ゲームのスクリプトを除いたサンドボックス内で同じ適用処理を使う。プレビューはゲームの保存データを読み書きしない。

編集データは専用のブラウザー下書き、および `.local-only/layout-editor/project.json` に保存する。JSON入出力と画面単位のリセットを用意する。保存だけでは本編や本番を変更しない。

採用するときは `node scripts/adopt-menu-layout.js .local-only/layout-editor/project.json` を実行し、`node scripts/build-game-entries.js` で配信識別子を再生成する。生成した設定だけをGitへ含め、ユーザーの編集ファイルは保持する。
