# 接触と判定結果の分離：Dev試作

## 目的と範囲

ヒヨコの広い受付時間でガード・被弾の確定音が遅れ、連撃の拍が変わって聞こえる問題を扱う。攻撃時計自体の累積ずれではない。ジャンプは成功後の描画だけで、攻撃時刻を変更していない。

Devの半拍前／一拍前／1.5拍前方式で試す。本編・「以前」の方式は従来どおり。バージョンはv0.9.6、公開は未実施。

試遊：<http://127.0.0.1:8006/dev.html?floor=5&enemy=guardian&practice=1&skin=chick&skinEffects=1&timingMode=onehalf&inputOffset=0&contact=1>

## 振る舞い

- 譜面の接触拍Cに、結果に依存しない40msの短い接触音を既存AudioContextへ予約する。BGMと同じorigin/beatを使う。
- 敵の反動と接触フラッシュもCから進める。ガード／被弾の確定で反動やフラッシュを最初から再生しない。
- 遅い入力を含む判定は従来の補正中心と受付幅で確定する。HP・コンボ・結果文字・成功反撃・ヒヨコのジャンプは結果側に残す。
- ガード／PARRY／JUSTの音は元のPCMの先頭を省き、Cから経過した位置の余韻を8msで立ち上げる。遅れた別の打撃音を重ねない。MISSの追加低音は省く。
- ミュート中も接触イベントは消費する。解除時に過去の接触を鳴らさない。結果との照合は譜面キーで行い、出力時刻補正の微小な更新に影響されない。
- 一時停止・勝利・曲切替では未来の接触予約を取り消す。すでに鳴った接触とその結果の余韻は残す。

通常の基準パリィ受付31ms、効果ありヒヨコ93msは維持。入力補正・拍列・BPM式・工房ポーズ・原画は変更しない。前の短い追撃復帰修正も継承する（[守護者の連撃](./GUARDIAN_COMBO_REVIEW.md)）。

## 確認と残る試遊

全Node463件成功。その後のミュート／時刻補正対策を含む最終差分では関連4件成功（全体は再実行せず、現在の追加1件を含む）。SFX5件、Python画像8件・フォント2件、変更JS構文・diff検査も成功。独立レビュー済み。

通常／ヒヨコ／効果OFF／ジャンプ無効 × ガード／被弾／JUST、各36回、合計432回の5ms刻みトレースで、接触音予約は全回C。拍列の累積ずれは浮動小数の丸め範囲内。これは予約時刻の検証であり、スピーカーの実測遅延ではない。遅め入力、補正±180ms、緩慢・安定性、一時停止／再開、勝利、ミュートも確認した。

実ブラウザで開始・戦闘・一時停止、警告／エラーなしを確認。音声比較は44.1kHz stereo、有限サンプル・クリップなし（新方式peak約0.0728）。証跡はGit管理外の `test-results/contact-presentation/`。

次はユーザーがヒヨコの守護者連撃で、共通接触音と結果の余韻のバランスを試す。特にガードの余韻がもう一打に聞こえないか、BGM中の合図が明瞭かは体感確認が必要。本編採用・公開はその後の別段階。
