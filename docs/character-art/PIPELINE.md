# キャラクター制作パイプライン v3 — 次のエージェントへの実施手順

開始地点：[README](./README.md)。ユーザーはまずキャラIDと依頼工程を指定する。現在の進捗を確認し、**完了していない前提条件を飛び越えない**。

## 基準と安全策

- **原画の見た目を直接トレース**して採用静止SVGへ持ち込む。以前の失敗は、原画を見ながら図形を目測で描き直したため別キャラになったこと。
- **立ち絵は戦闘待機ポーズ**。攻撃が動くことを最初から想定する。主人公では剣を肩付近、盾を胸前に構えるポーズが採用された。
- **SVG静止画を先に完成**させ、初めてパーツを分ける。最初から腕を回して見た目を確認しない。
- 以降の工程は [TRACING_AND_RIGGING](./TRACING_AND_RIGGING.md) に具体的なコマンドと判定を記載。
- **ゲーム判定・Web Audio・ゲームループの時刻、敵ステータス、保存領域を変更しない**。既存描画は戻せるよう残す。
- **Draft PR #28の同じブランチ**に作業する。新規PR・main更新・自動マージはしない。
- 自動テスト合格≠ブラウザ目視合格。見られなかった画面を「検証済み」と表現しない。

## フェーズA — ポーズ・画像案

1. [POSE_GUIDE](./POSE_GUIDE.md) とキャラ別 `prompts/<id>.md` を読み、敵と対峙する方向、立ち位置、攻撃部位、アイドル姿勢、溜め／反撃、接触／戻り、可動関節を確認。
2. [FLAT_VECTOR_SPEC](./FLAT_VECTOR_SPEC.md) と [SVG_BASE_GUIDE](./SVG_BASE_GUIDE.md) を読む。新規画像なら1体・全身・背景なし・色面のはっきりした**フラットベクター風**PNGを生成。余白を確保し、武器・盾・足が切れないこと。
3. **ユーザーに画像を提示し、ここで止まる。** 「採用」と明言されるまでGitHubへ採用素材として登録しない。別案の上書きも勝手にしない。

**成果**: 候補PNG、ポーズとデザインの説明。**承認ゲートA**: ユーザーによる下絵採用。

## フェーズB — 画像の固定・原画トレース

1. 採用された**同じ画像**を`assets/character-art/references/<id>/svg-base-approved.png`に**原寸・非減色で**登録し、`notes.md`に寸法・SHA256・採用日と承認内容を記す。読み込み権限やアップロード方法がない場合はその事実を明示してユーザーへ添付を求め、登録済みと偽らない。**ファイルが読めないときに推測でSVGを生成しない。**
2. `python scripts/trace-character-png.py <source.png> --out-dir assets/character-art/tracing/<id>` を出発点にする。現行スクリプトは主人公向けの**固定パレットと`hero-*`という出力名**なので、次の敵では**パレット・ファイル名・輪郭しきい値をキャラ別に調整**してから実行する。名前だけ変えて流用しない。
3. **原寸PNG→初期トレースSVG→静止清書SVG**。色境界と輪郭を抽出し、微小なノイズ・穴を除去するが、描き直して別のシルエットにしない。
4. PNGとSVGを同じ描画サイズで並べ、50%透過重ね合わせと差分を作る。**高さ96pxと128px**でも読み取れることを確認。
5. 静止SVGが元画像に十分一致しなければトレース工程へ戻る。**ユーザーが静止SVGを採用するまで次へ進まない。**

**成果**: 承認元PNG・生成スクリプト設定・中間SVG・清書静止SVG・比較PNG・縮小プレビュー。**承認ゲートB**: ユーザーによる静止SVG採用。

## フェーズC — マスク分割・関節リグ（主人公で成功した方式）

1. 採用した**同じ清書SVG**を読み込み、Canvas描画の上でマスクを使い**固定本体・頭・肩／肘（人型）・武器・防具**などを分離する。必要なら別SVGを使えるが、**元の静止SVGを手描きで作り直さない**。
2. 元絵で隠れていた関節面だけ最小限に補完する。元の色と輪郭を変えない。
3. 関節にpivotを付け、親子変換を固定する。人型の剣は**肩→肘→前腕＋握り手＋剣**。剣だけ回さない。スライムなど非人型は固有の伸縮・変形を使い、無理に肘を生やさない。
4. 元PNGと**idle時のパーツ再合成**を比較し、ずれ・重なり・欠けを検証する。
5. 各パーツの共通座標系・回転中心と表示順を`manifest.json`または記録用JSONへ残し、**ランタイムで使う値と一致するようにする**。

**成果**: 分割／マスク処理、リグ記録、idle合成比較。**ゲートC**: 静止SVGの見た目とリグの接続が保たれる。

## フェーズD — 試験描画とモーション

1. キャラID専用の**試験URLパラメータ**（例：`?art=knight-trace`）でのみ新描画を表示。従来版の描画経路と`?art=ready`主人公を壊さない。
2. `assets/game.js`で渡される既存の`charge`, `action`, `p`, `recoil`, `impact`などを利用。接触点・剣先の向き・到達距離は実装と照合し、**攻撃判定・タイムライン自体は変更しない**。
3. `idle`, `windup`, `strike`, `impact`, `recover`、必要に応じ`guard`で視覚検証。**剣柄と手が離れない・肘の裏が抜けない・装備の端が切れない・剣先が判定位置に合う**。
4. 96px、128px、通常画面、スマホ幅で確認。ブラウザ実機確認できなければ、条件付きの未検証として報告する。
5. Nodeテスト／構文テスト／Pages参照チェック／GitHub Actionsを確認し、PRに変更・URL・比較画像・未解決の点を記録。
6. **ユーザーがモーションを採用**してから、そのキャラの仕様として文書に確定。主人公のように方向と角度が決まったら、比較用の`spin`などは残しても、**採用版を該当試験モードのデフォルト**にする。

**成果**: 動く試験モード、比較ページ、テスト、レビュー結果。**承認ゲートD**: ユーザーによるアニメーション採用。**マージは別の明示指示が必要**。

## 引継ぎに必ず書く情報

キャラID、**どこまで承認されたか（A/B/C/D）**、実ファイルの場所（PNGとSVGを混同しない）、GitブランチとコミットSHA、SVGパレット・viewBox・原寸サイズ、可動のpivotと親子関係、接触点と表示時間、試験URL、実画面で何を確認したか、テスト結果、未解決の問題。勝手に「完成」と書かない。
