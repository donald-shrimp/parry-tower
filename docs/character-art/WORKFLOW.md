# キャラ画像生成 → SVG化 → ゲーム試験実装：制作フロー v2

## 必須のポーズ設計ゲート（2026-10-18追加）

**[POSE_GUIDE](./POSE_GUIDE.md) に従い、描く前に「敵の方向・待機構え・予備・攻撃・戻り・関節」を確認する。** 人型で剣や盾を使う場合、武器だけ・手首だけが回るモーションにならないように、肩と肘の運動を具体的に指定する。

- 主人公の以前のトレース方式は静止画の再現に成功した。**原画トレース→静止一致→分割**は維持する。
- 問題は元PNGが剣を下げた「飾りの立ち絵」だったこと。盾を構え、剣を肩の高さで保持した**戦闘待機PNG**に作り直す。
- 新PNGの採用前は旧 `?art=trace` も旧トレースSVGも変更しない。
- 分割後は**肩・肘・武器握り点**を独立で扱い、装備と手の接続を確認する。
- 追加のデザインが必要な場合、まず画像をユーザーに見せて承認を待つ。

## フェーズと承認ゲート

`キャラ固有仕様を読む` → **A. 設定画生成（任意）** → **人が設定画を採否判断** → **B. SVG制作用の簡略立ち絵1枚を生成** → **人が下絵を採否判断** → **原寸の承認PNGをブランチに登録** → **C. パーツ別SVGへ再設計** → **D. 実際のゲーム内ポーズをレンダリングして検査** → **人がSVGを採否判断**。

1. 設定画を作る担当は [CONCEPT_GUIDE](./CONCEPT_GUIDE.md) と `prompts/<id>.md` を使用。ここでは装備拡大や複数角度があってもよい。
2. 下絵担当は **[POSE_GUIDE](./POSE_GUIDE.md)**、**[FLAT_VECTOR_SPEC](./FLAT_VECTOR_SPEC.md)**、[SVG_BASE_GUIDE](./SVG_BASE_GUIDE.md) と対象 `prompts/<id>.md` を使用。主人公は [hero-svg-base.md](./prompts/hero-svg-base.md) を指定する。**1体・1ポーズ・陰影ゼロ・図形20〜30個程度の幾何学的フラット立ち絵**に厳格化。
3. 人が生成画像を**明示的に承認**するまでは、その段階のファイルを勝手にGitHubへ登録しない。
4. 承認後に画像を **原寸・非減色** のPNGとして `assets/character-art/references/<id>/svg-base-approved.png` へ置く。概念設定画を保持する場合は `concept-approved.png`。差し戻し時は同じファイルを上書きし、`notes.md` に採用の変更理由を残す。
5. SVG担当は [SVG_SPEC](./SVG_SPEC.md) を読み、**採用済み下絵の画像内容を実際に確認**した後に限り実装を開始する。パスがある／既存の`approved.png`があるという理由だけで進めない。
6. SVG担当は分割パーツ＋manifestを作成し、ゲームの判定やWeb Audioには一切触らず `?art=svg` 等の**試験表示だけ**に入れる。
7. **ゲームの実画面で**下記のポーズを画像・動画で確認する。問題があれば未完として修正し、ユーザーに採用を求めない。
8. 変更は常に既存の **Draft PR #28** のブランチのみ。新PRを立てたり、`main`へマージしたりしない。

## SVG下絵を承認する前の確認

- [ ] 余計な図版や設定資料ではなく、**1キャラ・全身・1ポーズのみ**
- [ ] 四辺に十分な余白（目安15%以上）、**盾と武器とマントの外側まで切れていない**
- [ ] 腕・剣・盾・腰布・脚が独立部位として判別できる
- [ ] ベース塗り4色以内＋必要なアクセント1色、影0、グラデーション0、金属反射0、内部装飾なし
- [ ] 約20〜30個の基本図形で説明できること（曲線を何十本も模写するようなら不採用）
- [ ] 2D平面・ほぼ一定幅の輪郭線で、ファンタジーのイラスト調になっていない
- [ ] 高さ96pxと128pxへの縮小でもキャラの役割を判別できる
- [ ] **待機姿勢から攻撃と防御へ肩・肘を使って自然につながる**
- [ ] 人が「この画像でSVG化してよい」と明示している

## SVGの完了ゲート（盾が切れた失敗への対策）

- [ ] 各SVGの **viewBox / width / height とパーツ実寸** が整合している
- [ ] 回転・移動を加えたときの**すべてのパーツ頂点の外接範囲**が意図せずクリップされない
- [ ] 盾・剣・マント・脚は待機・盾挙上開始・最大挙上・反撃・被弾反動で**切れ／消失／背景透け**がない
- [ ] 盾と握り手が離れず、腕の支点と重なり順が自然
- [ ] 武器先端と盾への見かけの接触位置を、ゲームの既存タイミングに合わせる
- [ ] ブラウザの**実画面スクリーンショット**を96px前後の表示サイズ、通常表示、拡大の3段階で確認。SVGファイルが構文上正しいだけでは合格にしない
- [ ] ビルド／CIが通り、旧描画へ戻せる
- [ ] ユーザーが完成SVGを**別途採用**した

SVGの具体的な検証手順は [SVG_SPEC](./SVG_SPEC.md) を参照。スクリーンショットやブラウザ実機を使えない場合、**目視済みと偽らず、未完として報告**する。

## 今回の失敗の記録（2026-10-18、hero）

- 1枚の設定画に三面図・拡大図・装備・分解図が混在し、主参照が不明瞭だった。
- さらにGitHubに登録した画像は原本1536×1024pxではなく、**128×120pxに減色した切り出し**だった。SVG化の詳細な根拠としては不足。
- 盾がゲーム内で欠けたことは、ディテールの問題とは**別に**、変換・viewBox・パーツ座標・ピボット・回転後の可視範囲の検証不足が疑われる。原因確定前にどれか1つだけのせいにしない。
- **結果**: 設定画の意匠の採用は取り消さないが、現行SVGは**不採用・旧比較用**。再生成する対象は先に「簡略立ち絵のPNG」で、勝手にSVGを上書きしない。

## やってはいけないこと

- 未承認の生成画像を「採用済み」として登録・実装すること。
- 旧来の `approved.png` を新しい `svg-base-approved.png` と同一視すること。
- イラストの見た目を合わせるために命中判定・盾受付時間・Web Audioの時計・保存データ・恒久強化を変更すること。
- `main` の直接編集、Draft PRの自動マージ、承認前のゲームへの本番反映。
