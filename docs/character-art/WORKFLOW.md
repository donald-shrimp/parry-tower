# 制作フローと承認ゲート

## 全体像

`指示書を読む → GPT Imageでキャラクター画像を生成 → 人間が採用・却下 → 採用画像だけアップロード → SVG担当が参照画像を読み込んでパーツ分割SVGを作成 → 試作ゲームで比較 → 人間が採用判断`

**画像生成担当とSVG化担当は別のエージェントでよい。** このリポジトリを唯一の共有仕様とする。

## フェーズA: 画像生成エージェント

1. [README](./README.md)、[STYLE_GUIDE](./STYLE_GUIDE.md)、対象 `prompts/<id>.md` を読む。派生種の場合は [VARIANTS](./VARIANTS.md) も読む。
2. **1キャラ・1提案画像**を基本に全身を生成。最初は立ち姿・中立ポーズ・3/4ビュー。ユーザーが望めば追加候補を生成する。
3. 頭、左右の上腕と前腕、手、胴、脚、武器・盾、マント／装飾などの境界を *絵として* 認識できるようにする。関節部分を大きな効果で隠さない。
4. 絵に余計な文字、UI、背景、台座、透かし、複数キャラを入れない。
5. **画像をユーザーに提示して終了。** GitHubへ無断アップロード、採用判定、SVG化、PRのマージはしない。

## フェーズB: 人間による選別と登録

1. チャットに出た絵から気に入ったものを **明示的に採用** する。却下画像はGitHubへ登録しない。
2. 画像をPNGで保存する。推奨: 単一キャラ、全身が欠けていない高解像度、背景なし（透過または均一背景）。元画像を勝手に加工したり、異なる案で上書きしない。
3. Draft PR #28のブランチ `experiment/character-art-canvas-v1` を選択し、`assets/character-art/references/<id>/approved.png` としてアップロード。**mainにはアップロードしない。**
4. キャラの採用理由や調整希望があれば `assets/character-art/references/<id>/notes.md` に残す（例: 「兜と配色を採用、武器は短く」）。
5. 複数のアイデアを採用したい場合はまず人間が1枚を「主参照」と指定し、他は `alternative-01.png` のように保存して優先順位を明示する。
6. 出典・権利上の制約がある素材は、アップロードする前に確認する。実在の第三者の画像を無断で参照として登録しない。

**採用条件**: `approved.png` が読めること、キャラIDが一致すること、ユーザーが採用を宣言したこと。ファイル名の存在だけで採用済みと推測しない。

## 現在の主人公(hero)進捗

2026-10-18にユーザーが設定画を採用。`assets/character-art/references/hero/approved.png`には容量を抑えた人物切り出し画像（128×120px）を登録し、原本1536×1024pxでないことを`notes.md`に記載。現在はSVGパーツ12点と試験描画`?art=svg`まで用意済み。**採用済みなのは参考画像であり、SVGデザインの実機採用ではない**。

## フェーズC: SVG制作エージェント

1. [SVG_SPEC](./SVG_SPEC.md)と対象キャラ指示書を再読し、**実際に`approved.png`の画像内容を視覚確認**する。GitHubファイルのバイナリが読めなければユーザーに画像を添付してもらう。
2. 原画を機械的に自動トレースするのではなく、輪郭と配色を尊重しつつ、ゲーム内表示サイズに合う面数・線幅で再設計する。
3. 頭、胴、腕、脚、武器、盾、布などを **別々のSVG** で制作し、各関節のピボット・重なり順・基準座標を manifest に記録する。
4. 元の既存Canvasモーションを調べ、**武器先端が盾へ触れる時刻・位置を変えない**こと。技術的な根拠は [SVG_SPEC](./SVG_SPEC.md) を参照。
5. SVGとmanifestを作成したら、色調、脚の接地、モーション中の隙間、当たり演出、モバイルサイズでの視認性を確認する。
6. 結果を **同じDraft PR #28にコミット**。新PRは不要。レビュー・採用・マージは人間の指示待ち。

## 絶対に守ること

- **作画のみ**。パリィ判定・Web Audio同期・敵の攻撃時刻・保存キー・恒久強化を変更しない。
- 既存描画は残す。現行試作の `?art=prototype` のように比較できる状態で検証する。
- 参照画像未採用／取得不可ならSVG制作を実行したことにしない。
- 出力が見栄えよくても *画像上の武器先端* と *ゲーム内の接触点* のズレを無視しない。
- `main` を変更しない。Draft PRはマージしない。必要ならPRごと閉じて破棄できる状態を維持する。

## キャラクターの完成条件

- [ ] 指示書と採用画像に一致
- [ ] 全身の輪郭が小サイズでも識別できる
- [ ] 必須パーツがSVGで独立している
- [ ] manifestにレイヤー順・ピボットがある
- [ ] 待機・予兆・攻撃・接触・反動で表示崩れがない
- [ ] 元のゲーム判定・拍同期が保持されている
- [ ] 旧版へ切り替えて比較できる
- [ ] 人間がスクリーンショット等でレビューできる
