# 原画トレース／パーツ分割／可動リグ：再現可能な技術手順

対応する制作ゲートは[PIPELINE](./PIPELINE.md)。**描き直したSVGではなく、採用PNGの色面と輪郭を直接ベクトル化したもの**を使用する。

## 1. 原画の登録と識別

- ファイルは**原寸PNG** `assets/character-art/references/<id>/svg-base-approved.png`。低解像度サムネイルや、別案のPNGを代用しない。SHA256／幅高さ／ユーザー採用の根拠を`notes.md`に記す。
- 透明PNGなら透明度を維持。白背景なら背景に接続した白領域だけ除去し、**白い兜・白い鎧を背景扱いで削除しない**。原画に同色の大面積がある場合はマスクを目視で検査。
- 他キャラは主人公と配色が異なるので、**画像の主要色からパレットを再抽出**。主人公の青・白・金を固定転用しない。

## 2. カラーマスクの抽出と静止SVG生成

実装例は [scripts/trace-character-png.py](../../scripts/trace-character-png.py) を読む。

```bash
python -m pip install numpy opencv-python
python scripts/trace-character-png.py path/to/approved.png --out-dir assets/character-art/tracing/hero
```

**注意**：現行の上記スクリプトは**主人公用**で、パレットと`hero-traced.svg`/`hero-static.svg`というファイル名が固定。新しい敵に流用するときは**ID・色パレット・大きさ・輪郭しきい値・背景処理を変更**し、入力画像の色と同じかを確認する。

基本ロジック：背景マスク→主要色量子化（RGB/LAB等）→領域ごと二値化→`findContours`で外形／穴を抽出→`approxPolyDP`で点数を減らす→色別パスにする。内側の穴を消すと兜や目が塗り潰されるため、**fill-rule=evenodd**等で維持する。

必要な調整は**小点ノイズ、輪郭のギザギザ、境界の白抜け**のみ。主人公の旧`hero-flat.svg`のようにAIが手で座標を推測して描き直す手順へ戻らない。

## 3. 品質測定と目視承認

- 原寸PNGとSVGを**同じ画面寸法へレンダリング**して並べる。
- 50%の透過重ね合わせと差分画像を作り、**兜・腕・武器・盾・マント・足**の輪郭、比率、配色を比較する。
- **高さ96pxと128px**の縮小を作り、ゲーム画面で認識できることを確認する。
- 差分・SSIM・色差などの数値は補助指標。見た目の一致やポーズの自然さを**数値だけで確定しない**。
- ここで一度ユーザーに静止SVGの採用判断を聞く。**ここを飛ばしてゲームに組み込まない。**

## 4. 静止SVGから意味のある可動部位へ切り出す

主人公の成功実装 [character-ready.js](../../assets/character-ready.js) を参照。

1. **静止SVG画像を読み込むのは1回**。同一画像をCanvas 2Dへ展開する。
2. 固定本体から、各可動領域の**輪郭マスクをdestination-outで削除**。ここをしないと動く盾／剣が二重に残る。
3. 可動部位側を**destination-inで切り出す**。切り出しポリゴンは画像の静止SVG座標のまま維持。新しい部品をSVGでゼロから描き直さない。
4. 隠れていた部分だけ、背景との境界が途切れないよう最小限補完（特に脇の下、肩裏、剣の手袋）。
5. レイヤーの親子関係とpivotを定義。**肩→肘→前腕＋握った手と剣**、盾なら盾腕→盾。人型以外では`core`/`tentacle`など生物に合った可動へ変更。
6. **idle時のすべてのパーツを原座標で再合成**し、静止SVGと比較する。腕・盾などを切ったせいで見た目が崩れたら切り出しを修正してから動かす。

元画像の解像度と実行時の`viewBox`／Canvasピクセル座標は対応するので、**切り出し後に個別の部品を中央配置・伸縮しない**。サイズ変換はすべてのレイヤーを束ねた外側で1回行う。

## 5. 変換と関節の回転

- 1箇所のpivotまわりなら`ctx.translate(px,py);ctx.rotate(angle);ctx.translate(-px,-py)`。
- 肩と肘を連動させる場合、**肩の変換が有効な内側で肘を回し**、剣柄が手から離れないことを確認。描画順／`save/restore`のバランスを保つ。
- **主人公の確定例**：肩0→−2π（−360°）、肘は同じ方向へ小さく追従、戦闘側が渡す**240msの`action`値**に合わせる。実コード [character-ready.js](../../assets/character-ready.js) の`armAngles`を参照。
- **敵は逆回転360°をコピーしない**。攻撃種に合わせて角度・方向・予備・振り下ろし／突き／伸縮／戻りを決める。`assets/game.js`では敵に`ctx.scale(-scale,scale)`の**水平反転**があるので、SVG座標とゲーム画面の左右を取り違えない。
- 殴打や突きのエンドポイントは`assets/enemy-motions.js`／`game.js`が扱う攻撃部位の**`(reach,-58)`**へ視覚的に届くかを確認。**描画の都合で攻撃判定や接触時刻を変更しない**。

## 6. 必須テストとレビュー

- 単体：SVGパス・パレット・viewBox・元画像との照合・切り出しマスクの存在
- リグ：肩／肘の順序、剣が前腕と一緒に回ること、idle合成、`ctx.save`と`restore`整合
- 動画／連番：idle→windup→strike→impact→recover（ガードがある敵はguardも）
- 実ゲーム：通常画面・96px・128px・スマホ幅、盾への届き方、見切れ、足元の浮き、フレーム落ち時の座標
- 同期：戦闘時計、着弾タイミング、Web Audio、パリィ入力が**変更されていない**
- フォールバック：新描画のロード失敗時に既存描画を維持し、`?art=<mode>`なしで動かないこと
- リポジトリ：テスト／CI／PR説明を更新。**採用の宣言はユーザーの目視フィードバックがあってから**。

## 過去の失敗からの注意

- 単純化を最優先して原画の輪郭を捨てない
- 元設定画の縮小コピーをSVG下絵の原本と取り違えない
- ゲームに先に組み込んでから静止画の出来を判断しない
- 盾や武器のマスク切り出しをせず二重表示にしない
- 剣だけ／手首だけを回して攻撃演出にしない
- `+360°`と`−360°`は**主人公でも見た目が大きく異なる**。採用したのは**−360°**。敵が一律同じとは限らない
