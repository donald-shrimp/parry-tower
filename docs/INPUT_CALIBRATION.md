# 入力補正と拍・接触の同期（2026-10-22）

ユーザーが1.5拍前の振りかぶり方式を実機で採用し、本編反映・公開を依頼。v0.9.5-preview-5から本編の標準にする。以前の接触=拍+100msの監査と履歴は[RHYTHM_SYNC_AUDIT](./RHYTHM_SYNC_AUDIT.md)、合図と追撃の詳細は[BEAT_CONTACT_REVIEW](./BEAT_CONTACT_REVIEW.md)を参照。

> ユーザー実機レビューで当たりづらさの指摘あり。現方式の「接触=拍+100ms」は「到達とビートが一致する」要件を満たさない。監査結果と旧キーなしの場合の100ms変化は[RHYTHM_SYNC_AUDIT](./RHYTHM_SYNC_AUDIT.md)を参照。以下は現実装の説明で、修正方針の最終承認ではない。

> 追加：拍と接触をそろえる[Dev候補](./BEAT_CONTACT_REVIEW.md)をローカルで試遊可能。公開版の方式と保存値は維持している。

## 目的と範囲

補正値は入力判定だけを動かし、敵の構え・振り・接触・カウントインは同じAudioContextの拍へ固定する。初撃と2拍以上空く攻撃は1.5拍前に振りかぶり、1.5拍以内の追撃は準備音と動作を省く。成功パリィは盾を8msで前へ出し、接触の最初のフレームで完全に前へ出す。長押しガードの100ms準備、判定幅、スキン効果、連打抑制、原画・手動ポーズは保持する。

## 時刻の関係

- B：音声出力時刻をperformance時刻へ対応付けた譜面の拍。個人の補正は含めない。
- 接触時刻C = B。本編とDevの採用方式に余分な100msを加えない。
- 入力中心J = B + 入力補正。＋は遅め、−は早めの入力を受け付ける。
- パリィ判定は `abs(押した時刻 - J) <= 既存の判定幅`。おすすめは測定誤差の中央値だけで、100msを加えない。

0msは聞こえた拍で押す基準。preview-4とpreview-5の入力中心JはともにB+補正なので、保存済み補正をリセットしたり、さらに100ms引いたりする必要はない。変わるのは接触位置と予備動作の時間関係であり、旧キーの換算や新キー優先は従来どおり。

有効な入力が先にあればCで確定する。まだ入力がなければ、Cと受付終了の両方を過ぎるまでガード/被弾を確定しない。境界の入力も受け付ける。ガードはC時点で構え終えていたかを記憶し、受付待ち中に離しても保持する。C後から構えたガードは遡って成立しない。フレーム間のrelease/cancel/blurでも記憶する。

受付待ち中の描画は、同じ譜面の次の攻撃予定とCからの経過を投影して振り抜きを続ける。ゲーム進行・次の敵・判定結果を先取りしない。遅れて成立した反撃エフェクトは有効入力時刻から開始し、通常の反撃はCから開始する。フレーム処理が遅れただけでは既存エフェクトを再スタートさせない。

## 測定と保存

3/2/1/GOの4拍後に16入力を測る。測定も実戦と同じpointerdownで取り、指を離した後のclickは重複集計しない。キーボード/支援技術のclickは維持する。外れ値除外・候補試奏・保存時のみ反映・取消は従来どおり。

新キー `parryTowerInputOffset_v1` を優先する。新キーがなければ旧 `parryTowerAudioOffset_v05` から100msを引いて仮読み込みする（±180msに制限）。旧キーは書き換えない。たとえば旧120msは新20ms、旧100msは新0msになる。初回/欠損/不正値は0ms。Devでは新キーにも保存しない。

測定には端末の残る遅延と利用者の押し方が含まれるため、ハードウェア遅延を厳密に単独測定するものではない。端末・音声出力を変えた際の体感は実機レビューが必要。
