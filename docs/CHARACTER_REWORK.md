# キャラクターの原画・可動化方針

## 現在の範囲

ユーザーが評価した錆びた騎士の線・塗りへ統一し、各敵の装備・色・攻撃の違いはmainを参考にする。図形のart=reworkと、再生成アトラスからの組立ては不採用。元PNGを直接マスク分割する。

主人公・騎士の採用方向が固まり、ユーザーの「mainを見て原画から各キャラのモーションまで制作。帰宅後にレビュー」に従い、敵14原画・派生込み26種まで実装済み。新しい絵と動きの最終採否はユーザーレビュー待ち。現行の詳細は [全キャラの可動化記録](./ROSTER_MOTION_REVIEW.md)、[原画と完全な生成プロンプト](./ENEMY_ART_CANDIDATES.md)。

## 保つ基準

- 騎士はv3原画の構え、右剣腕を最奥、左盾を最前面。赤い頭飾りはユーザー指定で一本に補修したPNGを使う。脚は一枚のまま。採用された背丈・間合い・強めた後退を保つ。
- 主人公は白銀・青・金の原画から6層。既存240msで正回転+360°し、斬撃中に上腕と前腕が一直線になる。ほぼ定位置で敵を迎える。今回の敵展開では変更していない。
- mainに近い背丈と、幅28%の主人公/73%の敵待機、地面80%。敵は後退で予告してから全身で接近し、接触・押し戻し・回復へつなぐ。
- スライムの圧縮、暗殺者の低い突き、亡霊の爪、番兵の大盾と剣、双剣の交互攻撃、詠唱の掌、機兵の歯車/ピストン、大剣ボスなど、種別ごとの予告と攻撃を保つ。
- スマホ舞台はmainの高さへ戻し、動作中の武器/布/後方の一部は見切れを許容。顔・主要な胴・接触点を優先する。

## 制作と実装

原画は内蔵imagegenで騎士を画風参照し、真の透明RGBAで保存。元PNG自体を保持し、生成記録に全文プロンプト・生成元・SHAを記す。新13体の分割座標・関節・描画順の正本はassets/character-enemy-data.js、可動化はassets/character-enemy-puppet.js。採用騎士/主人公は既存モジュールを使用する。

肩鎧を胴へ残して上腕だけを可動化し、肘→前腕→武器を剛体で接続する。隠れていた胴の補修は同じ原画の画素を小範囲に使い、元アルファと所有領域で制限して腕の奥へ描く。全身を別の絵に描き直さない。種類ごとの重なりを観察し、騎士の描画順を全キャラへ機械的にコピーしない。

元の腕・武器長で届く位置から接触を解き、既存時刻に主人公の盾へ合わせる。接触保持38msと反動は表示だけの処理。音声時計・判定・入力・ダメージ・保存形式には触れない。

確認ページと実戦で同じ描画を使い、原画再合成・関節長・接触点・脚固定・読み込み失敗時の両キャラfallback・ゲーム同一性を検証する。継続情報は [HANDOFF](./HANDOFF.md)。push/main更新/マージは行わない。
