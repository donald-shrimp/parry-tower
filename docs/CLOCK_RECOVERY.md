# 音声時計の異常時の復帰

## 目的と範囲

ユーザー報告は「弱回線で、立ち絵が見えBGMはずっと続くが戦闘が始まらない」。実機の根因は未確定。出力タイムスタンプの片側だけが進む状況を注入すると同じ症状を再現できたため、その経路を防御し、異常時の診断を残す。別に見つかった画像/JSONの無期限通信待ちは今回扱わない。魂の欠片の残高を塔貨の横へ追加する。

## 実装する一巡

1. 既存AudioContextの時刻対応だけを検証する純粋モジュールを追加。正常なgetOutputTimestampの換算と手動補正を維持する。
2. 非有限値/逆行/不整合/停滞した出力情報は使わず、同じAudioContext.currentTimeから換算。フォールバックへ増え続ける遅延を学習させない。
3. AudioContextの停止/中断/飛びを検知した場合、ダメージ処理前に一時停止。ユーザーの再開で同じ敵/HP/スキン/BPMの4拍へ戻る。ボス第二楽章も段階を保持する。
4. ページ内の有界な技術診断へ切替理由/回数/停止を追加。通信送信や診断の保存はしない。
5. 時計の片側停止、両側停止、例外/非有限値、正常出力遅延、キャンセル/補正、戦闘/第二楽章の復帰と判定、残高表示/更新を検証する。全体検証と公開確認を行う。

## 時計の選択

音声出力時刻からperformance時刻へ換算する通常経路は、[Web Audio仕様の換算式](https://webaudio.github.io/web-audio-api/#dom-audiocontext-getoutputtimestamp)に沿う。不正な値でこの式を使い続けると攻撃予定時刻を未来へ押し続け得るため、値と推移を検証する。代わりの音声時計やネット時計は追加しない。安全に換算できなければ敵を再抽選せず明示的に停止・再開する。
