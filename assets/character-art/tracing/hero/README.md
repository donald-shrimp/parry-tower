> **レビューステータス: 静止SVGの自動生成と比較まで。ユーザー未承認。**
> パーツ分割・ゲームへの組み込みは今回行わない。以前の `?art=flat` はそのまま保持。

## 入力（工程1）

2026-10-18にユーザーが選んだ、青マント・剣・単純な菱形紋章の盾を持つ騎士の **1254×1254px PNG** を入力とする。

- 元ファイル名：`a_clean_minimalist_vector_flat_cartoon_illustratio.png`
- SHA256：`e53c1090b43ea13da7a5f711177a0c16ebc8600ca4c3ddfa0ab4b35e1e9c5ff3`
- **GitHubブランチにはこの原寸PNGのバイナリをまだ登録していない**。チャット内の採用画像と成果物ダウンロードを参照する。GitHub上の以前の `references/hero/approved.png` は**別の画像**（128×120）なので流用しない。

## 工程2：元画像の多色トレース

OpenCVで背景につながる白領域を取り除き、主要色の領域を固定パレットへ分類。その境界を `findContours` で抽出。まず緩い単純化で中間 `hero-traced.svg` を生成する。

## 工程3：SVG清書

同じ輪郭を約1.75pxの許容差で簡略化し、微小な領域を省き、`hero-static.svg` を出力。元画像の**シルエット・兜・剣・マント・盾の位置**を直接継承する。既存の手描き `hero-flat.svg` を変換元にしない。

- **[清書した静止SVG](./hero-static.svg)** — 今回のPRでプレビューできるSVG
- **[ローカル重ね合わせ比較ページ](./compare.html)** — ブランチを配信し、元PNGをファイル選択してSVGと比較（画像は外部に送らない）
- [トレース再生成スクリプト](../../../../scripts/trace-character-png.py)
- 処理結果は**8色領域レイヤーのパス**。これは動かすパーツではない。

再生成する場合、リポジトリの任意のフォルダで：
```bash
python -m pip install opencv-python numpy
python scripts/trace-character-png.py /path/to/a_clean_minimalist_vector_flat_cartoon_illustratio.png --out-dir assets/character-art/tracing/hero
```

## 工程4：静止SVGと元画像の比較

制作セッションで元画像と清書SVGを1254pxにレンダリングして比較し、次の成果物を生成した（レビュー用ダウンロードは当該チャットの添付を参照）。

- `hero-static-comparison.png`：元PNG／清書SVG／50%重ね合わせ／差分画像
- `hero-static-96.png` と `hero-static-128.png`：ゲーム表示を意識した縮小プレビュー
- `hero-traced.svg`：より詳細な中間トレース
- 元のPNGとクリーンな静止SVGの目視比較で、**兜・大盾・剣・青いマントの位置と形はかなり近い**。ただし部分的に細線の境界や色差が残る。
- 色差の参考値：前景付近RGB平均絶対誤差 約19.7/255。全体SSIM 約0.857。これは**忠実さの補助指標であり、目視合格を保証する数値ではない**。

### 人間に見てほしいこと

1. 盾の五角形と金縁、菱形マークが元絵と重なるか
2. 兜の頭頂部・面頬・横の円形部の輪郭が自然か
3. マント端・剣先・ブーツに白い隙間や余計な突起がないか
4. 96px/128pxの表示でも顔、剣、盾を区別できるか

**承認されるまでゲームへの反映はしない**。次に進む場合は静止SVGを基準にパーツ化し、隠れた部分を補い、関節ピボットを明示してから動かす。これは以前の失敗を防ぐための必須ゲート。
